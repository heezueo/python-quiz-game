# 🐾 동물 퀴즈 게임

## 📖 프로젝트 개요

Python으로 개발한 콘솔 기반 동물 퀴즈 게임입니다.

사용자는 동물과 관련된 퀴즈를 풀고, 새로운 퀴즈를 직접 추가하거나 삭제할 수 있습니다.  
퀴즈를 풀면 점수가 기록되며, 최고 점수와 평균 점수 및 플레이 날짜와 시간을 확인할 수 있습니다.

프로그램을 종료한 후에도 퀴즈, 최고 점수, 점수 기록이 유지되도록 JSON 파일을 이용한 데이터 저장 및 불러오기 기능을 구현하였습니다.

이 프로젝트를 통해 Python의 클래스와 객체지향 프로그래밍, 함수 및 메서드 분리, JSON 파일 입출력, 예외 처리, Git 및 GitHub를 이용한 버전 관리 방법을 학습하였습니다.

## 🧩 클래스와 객체

### Quiz 클래스

`quiz.py`에 정의되어 있으며 하나의 퀴즈를 표현하는 역할을 합니다.

하나의 Quiz 객체는 다음 정보를 가지고 있습니다.

- 문제
- 선택지
- 정답
- 힌트

주요 메서드는 다음과 같습니다.

- `display()` : 문제와 선택지를 출력
- `check_answer()` : 사용자의 답을 정답과 비교
- `to_dict()` : JSON으로 저장할 수 있는 딕셔너리 형태로 변환

Quiz 클래스를 별도로 분리함으로써 하나의 퀴즈에 필요한 데이터와 기능을 하나의 객체로 관리할 수 있습니다.

### QuizGame 클래스

`quiz_game.py`에 정의되어 있으며 게임 전체의 진행을 담당합니다.

주요 역할은 다음과 같습니다.

- 메뉴 출력
- 퀴즈 진행
- 퀴즈 추가 및 삭제
- 퀴즈 목록 관리
- 점수 계산
- 점수 기록 관리
- JSON 데이터 저장 및 불러오기

즉, `Quiz`가 하나의 퀴즈를 담당한다면 `QuizGame`은 게임 전체를 담당합니다.

---

## 🏗 객체지향 프로그래밍을 사용한 이유

퀴즈 하나를 객체로 표현하면 문제, 선택지, 정답, 힌트를 하나로 묶어서 관리할 수 있습니다.

여러 개의 퀴즈를 관리할 때 각각의 데이터를 따로 관리하는 것보다 `Quiz` 객체를 여러 개 생성하여 리스트로 관리하는 것이 편리합니다.

또한 게임 전체의 기능은 `QuizGame` 클래스에 모아 퀴즈 데이터와 게임 진행 로직을 구분하였습니다.

함수만 사용하는 방식과 비교하면 관련된 데이터와 기능을 하나의 객체로 묶을 수 있고, 프로그램의 규모가 커졌을 때 각 기능의 책임을 구분하기 쉽다는 장점이 있습니다.

## 💾 JSON 파일 입출력

프로그램에서는 `state.json` 파일을 이용하여 데이터를 저장합니다.

### 저장되는 데이터

```json
{
    "quizzes": [],
    "best_score": 0,
    "score_history": []
}
```

### 각 데이터의 역할

#### quizzes

현재 등록된 모든 퀴즈를 저장합니다.

여러 개의 퀴즈를 관리해야 하므로 리스트 형태로 저장합니다.

#### best_score

지금까지 기록한 최고 점수를 저장합니다.

#### score_history

과거 플레이 결과를 저장합니다.

각 기록에는 점수와 플레이 날짜 및 시간이 포함됩니다.

예시:

```json
"score_history": [
    {
        "score": 4,
        "date": "2026-08-05 17:50"
    }
]
```

### JSON을 선택한 이유

JSON은 사람이 직접 읽기 쉬운 구조이며 Python의 딕셔너리와 리스트 구조와 잘 대응됩니다.

또한 별도의 데이터베이스를 설치하지 않아도 사용할 수 있고, 다른 프로그램이나 언어에서도 쉽게 읽을 수 있습니다.

따라서 간단한 콘솔 프로그램의 데이터를 저장하는 방식으로 JSON을 선택하였습니다.

## 🛡 예외 처리

사용자가 잘못된 값을 입력하거나 저장 파일에 문제가 발생하는 경우를 고려하여 `try / except`를 사용하였습니다.

### 입력 오류

숫자가 필요한 곳에 문자를 입력하는 경우 `ValueError`를 처리합니다.

```python
except ValueError:
    print("숫자만 입력해주세요.")
```

또한 문제 수와 정답 번호가 정해진 범위를 벗어나지 않도록 검사합니다.

### 프로그램 강제 종료

`Ctrl+C` 또는 EOF 입력이 발생한 경우에도 데이터를 저장한 후 안전하게 종료하도록 구현하였습니다.

```python
except (KeyboardInterrupt, EOFError):
    self.save_data()
```

### 저장 파일이 없는 경우

`state.json`이 존재하지 않으면 기본 퀴즈 데이터를 사용하여 프로그램을 실행합니다.

### 저장 파일이 손상된 경우

JSON 형식이 잘못되어 데이터를 불러오지 못하는 경우 `JSONDecodeError`를 처리하고 기본 상태로 실행하도록 하였습니다.

## 🔄 데이터 저장 및 복구

게임을 종료하거나 퀴즈를 추가하거나 삭제하거나 퀴즈 플레이가 끝났을 때 데이터를 저장합니다.

현재 프로그램은 별도의 서버나 데이터베이스 없이 `state.json`을 이용합니다.

저장 파일이 손상되거나 삭제된 경우에는 프로그램에 포함된 기본 퀴즈를 이용하여 다시 실행할 수 있습니다.

실제 서비스 수준으로 확장한다면 저장 전에 `.bak` 백업 파일을 생성하거나 여러 버전의 데이터를 보존하여 이전 데이터를 복구하는 방식을 사용할 수 있습니다.

## 📈 대규모 데이터 확장 시 고려사항

현재 프로그램은 퀴즈 데이터를 JSON 파일과 Python 리스트로 관리합니다.

퀴즈가 5개 정도일 때는 문제가 없지만 1000개 이상의 퀴즈가 저장된다면 다음과 같은 문제가 발생할 수 있습니다.

- JSON 파일의 크기가 커질 수 있음
- 프로그램 시작 시 전체 데이터를 불러와야 함
- 특정 퀴즈 검색 시 전체 리스트를 확인해야 할 수 있음
- 데이터가 많아질수록 메모리 사용량이 증가할 수 있음

따라서 실제 서비스 규모로 확장한다면 SQLite나 MySQL과 같은 데이터베이스를 사용하는 것이 적합합니다.

데이터베이스를 사용하면 필요한 퀴즈만 검색할 수 있고 인덱스를 이용하여 대량의 데이터를 효율적으로 관리할 수 있습니다.

## 🔀 Git 브랜치 및 병합

Git 브랜치는 기능별로 작업을 분리하기 위해 사용합니다.

예를 들어 퀴즈 풀기 기능을 개발할 때 다음과 같이 별도의 브랜치를 만들 수 있습니다.

```bash
git checkout -b play-quiz
```

기능 개발이 끝난 후에는 `main` 브랜치에 병합합니다.

```bash
git checkout main
git merge play-quiz
```

브랜치를 사용하면 기존의 안정적인 코드와 새로운 기능 개발 코드를 분리할 수 있다는 장점이 있습니다.

병합 과정에서 같은 부분을 수정한 경우 충돌(conflict)이 발생할 수 있으며, 이 경우 충돌을 해결한 후 다시 커밋하여 변경사항을 통합합니다.

## 📥 Git clone / pull

GitHub에 저장된 프로젝트를 다른 컴퓨터에서 사용하려면 다음과 같이 저장소를 복제할 수 있습니다.

```bash
git clone <GitHub 저장소 URL>
```

이미 프로젝트를 복제한 상태에서 GitHub의 최신 변경사항을 가져오려면 다음 명령어를 사용합니다.

```bash
git pull origin main
```

`git pull`을 사용하면 원격 저장소의 최신 변경사항을 현재 로컬 브랜치로 가져올 수 있습니다.
